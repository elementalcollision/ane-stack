## 1. What this project is

A vendored fork of [`savageAZfck/mil_spec`](https://github.com/savageAZfck/mil_spec) (© Adam Clark; upstream is MIT OR Apache-2.0 and the fork elects MIT, see `NOTICE` and `docs/LEGAL.md`). - hand-writes the CoreML `.mlpackage`/MIL format

- maps the ANE's internal resource model: io ports, the BAR pool, and the HWX records

## 2. The one rule that governs everything here

**Evidence, not documentation.** Every claim must be reproducible by a command whose output is recorded, and asserted by a spec that re-runs it. A spec only counts if it **can fail**: judge pass/fail by exit code (`want_rc`) and anchor counts with `$` (see `docs/evidence/SPEC.md`).

This handoff's first version broke the rule. Its spec passed while five headline laws were false: a pass check matched the failure text, and the generators never varied the dimension that mattered. Don't repeat that mistake.

```sh
cd vendor/mil_spec && cargo build --release -p milc && cd ../..   # plain `cargo build` does NOT build milc
./scripts/evidence-check.sh --require-all docs/spec/ane-port-limits-h17.spec   # the master spec; a SKIP must not pass
./scripts/evidence-check.sh --all --require-all                  # docs/evidence/*.spec AND docs/spec/*.spec (10 specs)
./scripts/apply-patches.sh --check                               # all 17 patches apply to pristine upstream (needs network)
./scripts/vendor-guard.sh --verify                               # vendored tree == manifest
bash tests/evidence-harness.sh                                   # the harness's own semantics (also in CI)
```

**`milc ane validate`/`compile` default to `--arch h16g` (M4).** Always pass `--arch h17` on this host. `milc ane run` ignores `--arch`.

**What CI covers.** GitHub Actions runs `vendor-guard.yml` (tree vs manifest, patches apply, guard test, harness test) and `hw-skip-discipline.yml` (one test binary, `mil_infer --test ops_e2e`, with `xcrun` shadowed). **CI cannot run any hardware spec.** Nothing on GitHub protects the ANE laws; they're protected only by running the spec on an Apple-silicon Mac. Do that after every change.

### The ANE resource model (lane/probe) — re-measured and re-evaluated 2026-10-22

The full writeup is `docs/spec/ane-port-limits-h17.md`. Every law there has a confidence label. Laws labelled *established* have a spec line that would fail if the law were wrong; laws marked *(runner-only)* do not. In short, for one `main` function on h17, macOS 26.7.1:

| Budget | Law | Spec § |
|---|---|---|
| Execution io cap | `live_in + n_states + unique_out + n_exposed_states ≤ 127`, with no floor. Liveness roots are the returned outputs **and every `write_state`**. Dead inputs and duplicate returns are free; the cap counts ports, not bytes. Never return an input unchanged: it comes back as zeros. | 1, 3 |
| Frontend io cap | `declared_in + n_states + out + n_exposed_states ≤ 255` (`MaxLiveInLiveOutExceeded`), on validate and compile; both count dead inputs | 2, 3 |
| State cap = BAR pool | 55 BAR ids, one per `__FVMLIB` segment. Each state surface owns a segment, and non-state io packs into one data + one const segment: `N_max = 55 − [any output] − [any plain input]`. That gives **53** with a plain input and **54** without; inline conv weights and LUT ops don't lower it. | 4 |
| Binding records | `0x9344` (primary source), `0x934a` (further source), `0x9442` (destination) are 12-byte records with slot word `0x2300 + 0x80·segment_ordinal`. Words below `0x2300` bind non-segment buffers (`fill`/inline constants, the >2 MiB `__DATA` scratch). `0x9344` is **not** a 54-entry state table. | 5 |
| Copy records | The tag is a presence-flag word (`0x9261 + 0x100·[dim1≠1] + 4·[dim0≠1] − [dim1=16]`); `dim2` or `dim3 = 256` emits none; stride = `8·min(⌈log2 dim1⌉, 4)`; the update-row record carries the shape | 6 |
| State execution | A state executes iff its 64 B row padding adds no 16 KiB page (`state_exec_predict.py`). `d3 % 32 == 0` is always safe; head_dim 80 fails from 86 rows. Allowed state dtypes: fp16, int16, int8, uint8, bool (not fp32/int32). | 7 |
| h16g vs h17 | Same **compile-time** caps and laws (cross-compiled; runtime caps unmeasured on M4); `0x934a` is emitted once per binary-add task on h16g and twice on h17 | 8 |

**What was wrong in the first version** (each item is now asserted the other way):
- an io "floor at 63"
- "53 states" as the cap itself
- a 54-record `0x9344` table ("WHY 54 resolved")
- a fixed `0x9361` read template
- stride `min(2·dim1+8, 32)`
- `0x9442` = 2N+1
- "one extra `0x934a` per program"
- a "constant payload 0x21"
- "53 states + 32/32 io" runs; it compiles but exceeds the execution cap

Each corrected law has a spec line that fails under the old claim. The first draft of the *rewrite* had nine errors of its own, which held-out testing caught before merge. They are listed under "Second-pass corrections" in the writeup; read that list, because it shows which extrapolations fail.

3. **Patches, not hand-edits, to `vendor/`.** Any change to the vendored tree needs:
   - a numbered patch in `patches/`
   - an entry in `PATCHES.md`
   - a row in FORK.md's modified-files table

   - a regenerated `vendor/manifest.sha256`

   Derive the patch from a **committed** diff against pristine plus all lower-numbered patches (`PATCHES.md`, `docs/evidence/0006-double-patch-and-stacking.md`); in practice the manifest sync is a separate commit. Watch for these:
   - ⚠️ **`apply-patches.sh --rebuild` would delete 8 tracked files.** `crates/mil_infer/examples/{cml_exec,e5_dual_path,e5exec,mk_minflex,predseg,probe_run2_state,seg4,shape_flex_e5rt}.rs` were added without a patch, and `shape-flex-matrix.spec` builds them. `--rebuild` uses `rsync --delete`. Fix this first with a patch that adds them (see §5).
   - ⚠️ `vendor-guard.sh --generate` refuses a dirty tree **only when `.git` is a directory**. In a linked git worktree the check is silently skipped.
   - Only 9 of the 23 files touched by patches carry a `FORK(ane-stack)` marker, and FORK.md's table lists only 5 files.
4. **Upstream's `vendor/mil_spec/ANE_FRONTEND_SPEC.md`:** no hand-edits. Extensions go in `docs/spec/`. A *correction* to a measurably wrong upstream claim goes through the patch mechanism, as patch 0015 did (`OWNERSHIP.md` clarification). ADR-0002 A.6 still has a pending correction assigned to L-PROBE.
5. **Don't depend on the deploy lane on macOS 26.7.1.** `docs/adr/0002-deploy-lane-closed.md`: self-emitted HWX doesn't deploy there, and Apple's own artifacts fail too. Its Appendix A records that on **macOS 27.0** (one M4 Pro host) an h16g artifact loads and runs, and Apple's H16 bundles load; the same model compiled `--arch h17` is still refused. The decision still stands, but it's an OS-version statement. That M4 is also the only 27.0 host, so any result there confounds SoC and OS. "Runs on the ANE" work targets the `e5rt` lane (`aned` compiles the MIL itself) or the CoreML lane.
6. **Fork-isolate every hardware probe.** ObjC exceptions abort the process, so run each probe as its own binary.
7. **Conventional commits:** `lane/<name>: <what>`. The body says what failed before, how it was verified, and the work-item ID. The work-item ID is the part most often missing; include it.

## 5. Open threads (where to continue, in priority order)

1. **Weights vs the BAR pool.** Inline conv weights (nested literal) compile, run, and leave the cap at 53/54; the conv's `__KERN_0` segment is shed. The open case is **BLOBFILE** weights, which is what real models use: `const`+BLOBFILE is rejected on h17 (`docs/spec/ane-frontend-h17.md`), because weights need the FileConstants lane. Probe that lane, or try weights fed as plain inputs (they cost io ports, §1). If BLOBFILE weights take a BAR id, real models get fewer than 53 states. Also open: why the pool is 55.
2. **Per-function and per-lane port caps.** Are 127 and 255 per function? Do multi-function programs and the CoreML lane share them? None of this is measured, and the scheduler needs it.
3. **State semantics and KV-cache shapes.** Already known: read-only states cost one port each. One skeptic read back a `noupd` program and found that the state persists, but no spec asserts it yet; make that the first new spec line. Still open:
   - runtime-position appends (every probe writes at `begin = [0,0,0,0]`)
   - multiple writes to one state, and cross-state copies
   - `[2L, kvh, S, hd]` KV layouts with a real S (e.g. 2048), checked for port cost, the page rule and the tentative row cap
4. **M4 silicon.** All h16g data is cross-compiled. Running on the M4 also means macOS 27.0, and that host has no Rust toolchain, so ship a prebuilt milc.
5. **Make `--rebuild` safe.** Add a patch (0018) that creates the 8 unpatched example files, then confirm `--rebuild` reproduces the tree byte for byte. Also clean up the other specs' weak assertions, which are L-TEST's:
